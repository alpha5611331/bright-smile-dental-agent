# Frontend (Next.js) working guide

The repository-wide rules in [`../CLAUDE.md`](../CLAUDE.md) and [`../SPEC.md`](../SPEC.md) apply here too.

@AGENTS.md

## Layout

```
src/
  app/                 routes (App Router). Server components by default.
  components/ui/       shadcn-generated primitives. Add with `pnpm dlx shadcn@latest add <name>`; do not hand-edit.
  components/<area>/   app components composed from ui/ (chat/, leads/, marketing/)
  lib/api/             client.ts (typed openapi-fetch client) + schema.d.ts (generated, never edit)
  lib/utils.ts         `cn()` helper
  env.ts               zod-validated server env (BACKEND_URL); the browser never sees it
```

## Rules

- Call the backend only through `api` from `@/lib/api/client` (same-origin `/api/*`, proxied by the rewrite in
  `next.config.ts`). No hard-coded backend URLs, no untyped `fetch` to the API.
- After any backend schema change: `uv run --directory ../backend python -m bright_smile.cli export-openapi`, then
  `pnpm gen:api`. CI fails if `openapi.json` or `schema.d.ts` drift.
- `cacheComponents` is on: data fetching is dynamic by default; opt into caching with `"use cache"` deliberately.
- Before committing: `pnpm lint && pnpm typecheck && pnpm format:check && pnpm build`.
- `AGENTS.md` is generated by `next dev` (it may contain characters our style rules ban); never edit it by hand.
